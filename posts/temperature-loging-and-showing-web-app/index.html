Live Temperature Monitor

  1. April 11, 2026
  2. 4 minutes

Scope of the project

  • Have the temperature logged and monitored via an web app.
  • The temperature records will then be used to show some graphs on the web interface.
  • The records coould also be used to train a AI to detect when is the most comfortable in the room, or in what climate I am, etc.
  • A small LCD screen to show the temperature live in the physical world too.

Hardware

  • Responsible for collecting the sensor data is my Arduino Uno.
  • The temperature sensor is a DS18B20 digital temperature sensor
  • The ‘Brain’ of the operation will be a 4GB Raspberry Pi 5

Connecting the two components

  • The Arduino and the Raspberry will be connected via a USB cable.
  • The Arduino sends the temperature on a new line every few seconds on a new line on the serial port.
  • The Pi the using a Python script reads the serial data using the serial library

Software

Frontend

  • For the frontend, the tech stack is the following

    • NodeJS
    • VueJS as the main framework
    • ChartJS for the graphs
    • Axios for consuming APIs
    • Vite for building the project easily

  • The server is hosted using nginx* on the Pi

Steps in developing

  1. Install NodeJS and npm

    sudo apt update
sudo apt install nodejs npm

  2. Creating the project using Vite’s VueJS template

      npm create vite@latest tempWebsite -- --template vue

  3. Install all the libraries using npm

     npm i chart.js vue-chartjs

  4. Develop locally

      npm run dev

  5. When ready, build the frontend

      npm run build

  6. Sync the website with the /var/www/ in order for the nginx server to pick-up the changes

    sudo rsync -av --delete dist/ /var/www/html/tempWebsite

  • The frontend will be split into Components which will be then ‘glued’ together in the App.vue.

  • There will be two components on the frontend:

    • SensorValue.vue, responsible for fetching the sensor data and displaying it.
    • SensorChart.vue, responsible for fetching latest n datapoints and plotting them on the UI.

  • Also, in order for the data to be updated without the user refreshing the page, both components are using the setInterval() to autoupdate at a certain time interval.

Backend

  • For the backend, the tech stack is as follows:
    • Python for Arduino interaction, as well as the API using FastAPI.
    • PostgreSQL for storing the temperature and timestamps
    • A bit of bash scripting for implementing a cron job on the server.
    • Nginx for hosting the server
    • Cloudfare Quick Tunnels, for deploying the app on the world wide web :)

API structure

  • GET /api/temp –> fetches the latest sensor reading from the serial

    • Response of the form: 
       {
 "temperature": "22.31",
 "time": "11:23"
 }

  • GET /api/temp/{limit} –> fetches the limit number of data entries in the database

    • Response of the form:
    {
"data": [
   [
       22.31,
       "11:25:01.326369"
   ],
   [
       22.31,
       "11:20:01.223722"
   ],
   [
       22.37,
       "11:15:01.124951"
   ],
   [
       22.44,
       "11:10:01.039853"
   ]
]
}

  • GET /api/log/temp –> fetches the data from the sensor then logs it in the database

    • Response of the form: 
      {
     "message": "Data logged successfully",
     "temperature": "22.25",
     "time": "2026-04-12T11:31:04.185219"
 }

Configuring the nginx server

  • The server acts as a reverse proxy

  • The following is the config file

    server {
  listen 80;
  server_name YOUR_SERVER_NAME;

  root /var/www/tempWebsite;
  index index.html;

  location / {
      try_files $uri $uri/ /index.html;
  }

  location /api/ {
      # This points to your actual Python/Node API running locally
      proxy_pass http://127.0.0.1:8080;

      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
  }
  }

  • Then to check that the config file is valid run:

      sudo nginx -t

  • If all is good, restart the nginx server

    sudo systemctl reload nginx

  • To start the Cloudfare website run (make sure it is installed):

     cloudflared tunnel --url http://localhost:80

    The app will be live on the specified URL
